# Nursing AI — PostgreSQL

منصة تعليمية لطلاب التمريض: حسابات، محادثات ذكاء اصطناعي، صور، وقاعدة معرفة.

## النشر على Dokploy

1. أنشئ **Database → PostgreSQL** باسم خدمة مثل `nursing-ai-db` واسم قاعدة `nursing_ai`. صورة `postgres:18` العادية تعمل؛ لا تحتاج Supabase أو pgvector. شغّل قاعدة البيانات واحتفظ بكلمة المرور.
2. في خدمة التطبيق اربط مستودع `d11fy/Nursing-AI`، فرع `main`، والمسار `/`. اختر **Nixpacks**؛ ملف `nixpacks.toml` يضبط Node.js 22 وأوامر البناء والتشغيل.
3. في **Environment** أضف المتغيرات التالية واحفظها:

| المتغير | القيمة |
| --- | --- |
| DATABASE_URL | رابط الاتصال **الداخلي** من خدمة PostgreSQL؛ يجب أن تكون الخدمتان على شبكة تسمح بالاتصال |
| APP_URL | رابط الموقع الكامل باستخدام HTTPS |
| AUTH_SECRET | قيمة عشوائية سرية بطول 32 حرفًا على الأقل |
| AI_PROVIDER | `openai` أو `ollama` |
| OPENAI_API_KEY | مطلوب فقط عند اختيار `openai` |

ولّد AUTH_SECRET على جهازك بهذا الأمر؛ لا تنشر القيمة في GitHub:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

4. أضف دومين في **Domains** واجعله يوجّه إلى منفذ التطبيق `3000`، وفعّل HTTPS. لازم يطابق الرابط قيمة APP_URL؛ جلسات الدخول تستخدم cookies آمنة تتطلب HTTPS في الإنتاج.
5. انشر التطبيق. أمر البناء `npm run build`، وأمر التشغيل `npm run start`. لا تستخدم `npm run dev` أو `next start` مباشرة في إعداد Dokploy، لأن أمر التشغيل الخاص بالمشروع يتحقق من الإعدادات وينشئ الجداول قبل تشغيل الموقع.
6. افتح `/register` وأنشئ حسابًا. لترقيته إلى مدير نفّذ من طرفية **حاوية التطبيق**:

```bash
npm run admin:promote -- your-email@example.com
```

المخطط في `database/0001_init.sql`. ينفّذ تلقائيًا مرة واحدة، داخل transaction وبقفل لمنع السباق بين نسخ التطبيق. المواد الافتراضية في `database/seed.sql`. فشل الإعداد يوقف تشغيل التطبيق بدل تشغيل موقع ناقص. استخدم **قاعدة جديدة مخصصة لهذا المشروع**؛ السكربت يرفض قاعدة تحتوي أصلًا على جدول profiles بدون سجل ترحيل.

## ما تم استبداله

- الاتصال عبر pg بحد أقصى 5 اتصالات لكل عملية تطبيق.
- كلمات مرور مشتقة باستخدام scrypt مع salt عشوائي، وجلسات عشوائية مخزنة كبصمات SHA-256 داخل PostgreSQL.
- التحقق من ملكية البيانات في طبقة الوصول من السيرفر، وليس الاعتماد على الواجهة. الحساب الموقوف لا يستطيع استخدام جلساته. قاعدة البيانات ليست واجهة عامة؛ لا تعرض منفذها للإنترنت.
- الصور والمستندات محفوظة كبيانات binary في PostgreSQL. نسخ قاعدة البيانات الاحتياطي يشملها؛ لا تحتاج volume إضافيًا للتطبيق. الصور بروابط موقعة لمدة ساعة. الحد الأعلى للصورة 8MB وللمستند 10MB.
- البحث الدلالي يستخدم مصفوفات PostgreSQL بأبعاد مأخوذة من استجابة موديل التضمين، وcosine similarity داخل SQL، بدون إضافة pgvector. لا يقارن إلا مقاطع من نفس المزوّد والموديل وعدد الأبعاد. البحث يفحص المقاطع المؤهلة؛ مناسب للبداية ويحتاج فهرسة متجهية أو خدمة مخصصة عند نمو قاعدة المعرفة.

هذا إعداد لقاعدة جديدة، **لا ينقل تلقائيًا** حسابات أو ملفات Supabase الموجودة بالسيرفر السابق. ملفات `supabase/` القديمة مرجع تاريخي فقط، لا تشغّلها على القاعدة الجديدة.

## استعادة كلمة المرور

أضف SMTP_HOST وSMTP_PORT وSMTP_USER وSMTP_PASSWORD وSMTP_FROM في Environment لتفعيل رسائل الاستعادة. إذا لم تُضبط خدمة البريد، تظهر رسالة واضحة للمستخدم ولا يدّعي التطبيق إرسال رابط. الرابط صالح 30 دقيقة ولمرة واحدة؛ تغيير كلمة المرور يبطل الجلسات السابقة. التسجيل لا يتطلب تأكيد البريد في هذه النسخة.

## Local Ollama Setup

ثبّت [Ollama](https://ollama.com/download)، ثم نزّل موديلات النص والصور والتضمين:

```bash
ollama pull qwen2.5:3b
ollama pull qwen3:4b-instruct
ollama pull qwen3-vl:4b-instruct
ollama pull nomic-embed-text
ollama serve
```

إذا كانت خدمة Ollama تعمل أصلًا، لا تحتاج تشغيل `ollama serve` مرة ثانية. يستخدم التطبيق HTTP API مباشرة: `/api/chat` مع `think: false`، و`/api/embed` للتضمين. لا يلزم مفتاح OpenAI في الوضع المحلي. يستخدم `qwen3-vl:4b-instruct` لتحليل صور المحادثة والصور التعليمية، بينما تبقى ملفات PDF وWord وPowerPoint والنصوص على مسار استخراج النص والفهرسة الحالي. تكلفة Ollama المسجلة في التطبيق صفر، ولا تمثل تكلفة تشغيل جهازك.

انسخ `.env.example` إلى `.env.local` واضبط اتصال PostgreSQL وقيمة AUTH_SECRET، واستخدم محليًا:

```ini
APP_URL=http://localhost:3000
AI_PROVIDER=ollama
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_CHAT_MODEL=qwen3:4b-instruct
OLLAMA_VISION_MODEL=qwen3-vl:4b-instruct
OLLAMA_EMBEDDING_MODEL=nomic-embed-text
```

```bash
npm ci
npm run db:migrate
npm run knowledge:reindex
npm run dev
```

افتح `http://localhost:3000`. أمر إعادة الفهرسة يتجاوز قاعدة المعرفة الفارغة تلقائيًا. لا يشغّل التطبيق تنزيل الموديلات تلقائيًا؛ أخطاء الاتصال أو الموديل المفقود تشرح الخطوة المطلوبة.

داخل حاوية Dokploy، العنوان `127.0.0.1` يشير لحاوية التطبيق نفسها. اضبط `OLLAMA_BASE_URL` على عنوان خدمة Ollama القابل للوصول من شبكة الحاوية، مثل `http://ollama:11434` عند وجود خدمة بهذا الاسم على نفس الشبكة. لا تعرض Ollama للإنترنت دون حماية. يحتاج تشغيل الموديلات ذاكرة إضافية؛ نقل التطبيق لا يجعل السيرفر الصغير قادرًا تلقائيًا على استضافة الموديل أيضًا.

عند استخدام Ollama على جهاز شخصي مع نفق SSH إلى السيرفر، يمكن ربط منفذ النفق بعنوان شبكة Docker داخل السيرفر. مثال لإعداد نفق يستمع على `172.17.0.1:11435`: اضبط `OLLAMA_BASE_URL=http://172.17.0.1:11435`، ثم اختبر `/api/tags` من **حاوية التطبيق** قبل النشر؛ نجاح الطلب من طرفية السيرفر وحدها لا يثبت وصول الحاوية. يجب أن يبقى الجهاز الشخصي وOllama والنفق شغّالين؛ عند إعادة تشغيل الجهاز شغّل النفق مجددًا. عنوان شبكة Docker يختلف بين السيرفرات، فلا تنسخ المثال دون التحقق.

### ترحيل وإعادة فهرسة المعرفة

`database/0002_embedding_spaces.sql` تُطبّق مرة واحدة بواسطة `npm run db:migrate` أو تلقائيًا عند `npm start`. لا تعدّل `0001_init.sql` المطبقة سابقًا. الترحيل يزيل قيد 1536 ويحفظ المتجهات القديمة دون تخمين مصدرها، لكنه يستبعدها من البحث حتى تُعاد فهرستها. عدد أبعاد التضمين يُقرأ من الاستجابة الفعلية، وليس ثابتًا في الكود.

بعد التحديث، أو تغيير المزوّد أو موديل التضمين (حتى لو له نفس الأبعاد)، نفّذ من مجلد التطبيق وبنفس إعداداته:

```bash
npm run knowledge:reindex
```

هذا الأمر يعيد معالجة **كل الملفات الأصلية المحفوظة في PostgreSQL** بالتتابع مع قفل يمنع معالجتين متزامنتين. يستبدل مقاطع الملف الحالي، ويجعله قابلًا للبحث بعد اكتماله فقط. عند الفشل يتوقف الأمر بخروج غير صفري، ويظهر الملف بحالة فشل؛ أصلح السبب ثم أعد الأمر أو اختر «إعادة المعالجة» للملف من لوحة الإدارة → قاعدة المعرفة. الملفات الأصلية والحسابات والمحادثات لا تُحذف. احتفظ بنسخة احتياطية قبل ترحيل قاعدة الإنتاج.

للتبديل إلى OpenAI اضبط `AI_PROVIDER=openai` و`OPENAI_API_KEY` ثم أعد تشغيل التطبيق وأعد الفهرسة. وللعودة إلى Ollama اضبط `AI_PROVIDER=ollama` ثم أعد التشغيل والفهرسة. لا يحدث fallback تلقائي إلى OpenAI. عند تحديث أوزان موديل محلي تحت الاسم نفسه أعد الفهرسة أيضًا؛ لا تغيّر الأوزان أثناء عملية الفهرسة.

مرجع البروتوكول: [Ollama chat API](https://docs.ollama.com/api/chat)، [Ollama embed API](https://docs.ollama.com/api/embed).

## الفحوص

Node.js 22.18+ موصى به. انسخ `.env.example` إلى `.env.local` واضبط قاعدة تطوير.

```bash
npm ci
npm run db:migrate
npm run dev
npm test
npx tsc --noEmit
npm run lint
npm run build
```

الاختبارات تستخدم PostgreSQL مضمّنًا عبر PGlite في الذاكرة وHTTP mocks لـOllama، ولا تتصل بقاعدة الإنتاج أو بموديل محلي. تغطي الترحيل والصلاحيات وSQL والملفات وكلمات المرور وبث Ollama وعزل المتجهات غير المتوافقة. لا تختبر جودة إجابات الموديل أو أداء جهازك.

البناء يستخدم Webpack مع تقليل ذاكرته وعامل واحد لتوليد الصفحات، وفحص TypeScript مفعّل. هذه الإعدادات لا تضع حدًا إجماليًا لذاكرة البناء. لا تبنِ على VPS مزدحم؛ يمكن بناء صورة في CI ونقلها للاستضافة عند الحاجة. معالجة ملفات PDF/DOCX ما زالت متزامنة داخل الطلب، لذا المستندات المعقدة قد تحتاج موارد أكبر.

التطبيق للتعليم فقط، وليس لاتخاذ قرارات علاجية.
