# Nursing AI — Personal Tutor

منصة لطلاب التمريض تحفظ الحسابات، السنوات والمواد، الاشتراكات، المحادثات، ملفات الطالب ولوحة الإدارة. طبقة التدريس الجديدة تعتمد OpenAI Responses API ونموذج `gpt-6-luna` وحده للمحادثة والصور والتلخيص والأسئلة والذاكرة، و`text-embedding-3-small` بتضمينات 1536 للبحث. لا يوجد تبديل تلقائي إلى مزود أو نموذج آخر.

**حالة هذا التغيير:** تحقق محليًا؛ لم يُطبّق على قاعدة الإنتاج ولم يجتز بعد التقييم الطبي الحقيقي المطلوب. التفاصيل في [تقرير إعادة البناء](docs/ai-rebuild-report.md).

## إعداد الاستضافة على Dokploy

عنوان قاعدة البيانات الداخلي يعمل من حاوية التطبيق على الخادم. لا يلزم فتح PostgreSQL للإنترنت. تشغيل أدوات المشروع من جهاز آخر يحتاج اتصالًا خاصًا بالخادم أو نسخة اختبار محلية.

1. احتفظ بالقاعدة الحالية وبياناتها وملفاتها الأصلية. جهّز نسخة اختبار منفصلة واستعادة موثقة للنسخة الاحتياطية قبل تحديث الإنتاج.
2. PostgreSQL يحتاج امتداد `vector` مثبتًا على الخادم؛ يجب أن يستطيع حساب الترحيلات إنشاء الامتداد. لا تفترض أن صورة PostgreSQL العادية تتضمن pgvector. لا تستبدل أو تمسح مجلد بيانات PostgreSQL أثناء الإعداد.
3. في خدمة التطبيق → Environment، اضبط قيم `.env.example` السرية مباشرة. `OPENAI_API_KEY` يجب أن يكون صالحًا وقادرًا على الوصول إلى النموذج المطلوب. احفظ الإعدادات وأعد تشغيل التطبيق عند تغيير المفتاح.
4. `DATABASE_URL` لحساب تشغيل لا يمتلك `SUPERUSER` أو `BYPASSRLS`. `MIGRATION_DATABASE_URL` لحساب DDL مستقل على نفس القاعدة. يلزم منح حساب التشغيل استعمال المخطط والجداول والتسلسلات الجديدة بعد الترحيل. يفشل التطبيق في الإنتاج إذا كان حساب التشغيل يتجاوز RLS.
5. `APP_URL` يطابق دومين HTTPS، و`AUTH_SECRET` قيمة سرية عشوائية لا تقل عن 32 حرفًا. Node.js 22.18 أو أحدث؛ البناء `npm run build` والتشغيل `npm start`.

### النسخ الاحتياطي والترحيل

نسخة المستودع لا تحفظ الملفات الأصلية: الملفات مخزنة في PostgreSQL. يلزم `pg_dump` متوافق مع إصدار الخادم وصلاحيات قراءة جميع البيانات والملفات.

من طرفية حاوية التطبيق/بيئة خاصة متصلة بقاعدة الاختبار:

```bash
npm run db:backup -- /private/backups/nursing-ai
```

يفضّل أن يكون هذا المجلد وحدة تخزين دائمة خارج ملفات النشر. اضبط `BACKUP_RECEIPT=/private/backups/nursing-ai/latest-backup.json` في Environment. افحص ملف التفريغ بـ `pg_restore --list` واستعده في قاعدة منفصلة؛ إيصال وجود الملف لا يثبت صحة الاستعادة وحده.

```bash
npm run db:migrate
npm run ai:preflight -- --model
npm run knowledge:reindex
npm run knowledge:reindex -- --run --stale-only
```

`knowledge:reindex` دون `--run` يعرض خطة فقط. التنفيذ يسجل مهام دائمة، ولا يعتمد الملفات المشتركة تلقائيًا. `--include-private` يضيف ملفات الطلاب إلى فهارسهم الخاصة؛ `--process` ينفذ المعالجة مباشرة. يلزم إيصال النسخة الاحتياطية عند الترقية لقاعدة موجودة وعند إعادة الفهرسة. `npm start` يشغّل الترحيلات أيضًا، ولذلك لا تنشر فوق قاعدة موجودة قبل إكمال هذه الخطوات ومنح الصلاحيات.

الترحيل `0016` إضافي ويحفظ فهارس النظام السابقة، الإجابات والتدريب والحسابات. لا يتعامل مع الذكريات القديمة المولدة آليًا على أنها إتقان موثوق. المصادر المشتركة تحتاج مراجعة وتفعيلًا من `/admin/knowledge` بعد نجاح المعالجة؛ المواد والسنوات المسموح بها تقيد وصول الطالب.

## كيف يعمل التدريس

يفهم النظام المادة من مواد الطالب، ويسترجع مقاطع باستخدام pgvector والبحث النصي والألفاظ الطبية وأولوية المصدر والصفحة. اختيار المادة يعزز مصادرها؛ يمكن استرجاع مادة أخرى مسموحة إذا كان السؤال متعلقًا بها. يستخدم 5–10 مقاطع عند توفرها، ولا يرسل الكتاب كاملًا في كل سؤال. ترتيب المصادر يعتمد نوعها ومراجعة المشرف؛ سؤال الامتحان غير المحلول لا يثبت صحة جوابه.

الإجابة تذكر مصادر المنهج أو الملف الشخصي عند استخدامها. المفاهيم التمريضية العامة الثابتة مسموحة عندما لا توجد مادة مناسبة، وتُسجّل كمعرفة عامة. الجرعات والقيم الطبيعية والبروتوكولات تحتاج أدلة اقتباس متطابقة وأرقام مسندة؛ عند غيابها يطلب النظام توضيحًا. فحص الاقتباس والأرقام لا يثبت وحده صحة كل استنتاج طبي، لذلك يبقى تقييم المدرّس شرط قبول.

تبث الإجابات العادية تدريجيًا. تُحجز الإجابات المتعلقة بالقيم السريرية حتى انتهاء فحص الأدلة. تفكير النموذج الداخلي لا يظهر للمستخدم. سؤال التدريب تفاعلي واحد، ومفتاحه محفوظ على الخادم؛ تسجيل الإجابة الصحيحة أو الخاطئة يجري مرة واحدة دون منح إتقان لمجرد فتح الصفحة أو إرسال رسالة.

## الصور والملفات والذاكرة

تحليل الصورة محفوظ حسب الطالب وبصمة الصورة، ومتابعات مثل «الجزء الأول» و«كمل» تستخدم الأقسام المحفوظة. رفع PDF وDOCX وPPTX وTXT متاح من المحادثة. معالجة الملفات تمر بصفوف أعمال دائمة قابلة للاستئناف، وتستبدل المقاطع ذريًا بعد نجاح جميع التضمينات. الاستخراج والتضمينات والمحتوى الدراسي القابل لإعادة الاستخدام محفوظة لتقليل الاستدعاءات المتكررة.

PDF يحفظ الصفحات ويستخدم الرؤية للصفحات المصورة والرسوم. `KNOWLEDGE_MAX_OCR_PAGES` يحد عدد الصفحات البصرية؛ تجاوز الحد يفشل صراحة دون اعتماد فهرس جزئي. DOCX يحفظ هيكل العناوين والجداول. PPTX الذي يحتوي رسومًا يحتاج LibreOffice لتحويل الشرائح كاملة؛ عند عدم توفره يُطلب تصدير PDF بدل فهرسة نص جزئي. المسح غير الواضح والعلاقات المعقدة في الجداول تتطلب مراجعة فعلية.

ملفات الطالب خاصة. لا تصبح مشتركة إلا بموافقتين صريحتين ومراجعة المشرف. الأصل يُحذف بعد عشرة أيام وفق سياسة الاحتفاظ، ويبقى النص المستخرج والمحتوى الدراسي. الملفات الأكبر من 20MB تتطلب إقرار سياسة الاحتفاظ؛ الحد الافتراضي للرفع 50MB.

الذاكرة تحفظ الموضوع والملف والصورة والصفحة وسؤال التدريب، والأخطاء المقيمة والأهداف والتفضيلات الصريحة. ملخص المحادثة يتجدد دوريًا ويستخدم مع أحدث الرسائل، ويمكن استئناف الجلسة من محادثة جديدة.

## الإدارة والتكلفة

`/admin/knowledge`: حالة الاستخراج والفهرسة، الصفحات والمقاطع والتضمينات، المعاينة، أولوية المصدر والتفعيل، تغطية المواد والفجوات. `/admin/ai-system`: النموذج الوحيد وصحة المعالجة. `/admin/ai-usage`: الاستهلاك حسب الطالب والميزة واليوم والشهر. تتبع الرسالة يعرض الاسترجاع والمراجع ومستوى الاستدلال والتكلفة والزمن دون عرض التفكير الداخلي.

السعر المحسوب تقدير من usage الفعلي مع فصل الرموز المحفوظة وإصدار جدول التسعير. الطلب الذي ينقطع قبل إرجاع usage قد يسجّل تكلفة غير معروفة كصفر؛ طابق الإجمالي مع فاتورة المزود، ولا تعتبر السجل ضمانًا للمبلغ المفوتر.

## التحقق والقبول الفعلي

```bash
npm test
npx tsc --noEmit
npm run lint
npm run build
```

الاختبارات المحلية تستخدم PostgreSQL عبر PGlite مع pgvector واستجابات OpenAI محاكية؛ تثبت عقود التنفيذ والعزل والحفظ، ولا تقيس جودة تعليم النموذج الحقيقي.

للتقييم الحقيقي على نسخة اختبار تحتوي منهجًا معتمدًا، اضبط متغيرات `EVALUATION_*` في `.env.local` أو Environment. حضّر المسودة بحساب مشرف، ثم راجع أسئلتها وإجاباتها واقتباساتها بشريًا وغيّر `reviewed` لكل سؤال تمت مراجعته:

```bash
npm run evaluate:prepare -- --live
```

التقييم يحتاج 100 سؤال على الأقل يغطي تعريفًا، اختيارًا متعددًا، شرحًا، مقارنة، صورة، دواء، مختبرًا واستدلالًا سريريًا، مع إعادة صياغة عربية لمصادر إنجليزية. استخدم حساب طالب اختبار له المواد المطلوبة وحصة كافية؛ لا تغيّر حدود حسابات الإنتاج. هذا التقييم يستهلك رصيدًا ويسجل محادثات وأحداث تعلم فعلية.

```bash
npm run evaluate:e2e -- --live
npm run evaluate:tutor -- --live
```

الأول يحتاج صورة المجهر الفعلية وPDF بخمس صفحات على الأقل، ويختبر المتابعة والسؤال والتصحيح والذاكرة والاستئناف والمعرفة العامة وطلب التوضيح. الثاني يختبر المنهج عبر HTTP موثق ويحفظ النتائج في `.evaluation/`. أضف مراجعات المدرّس في `EVALUATION_REVIEWS` و`EVALUATION_E2E_REVIEWS` واربط `EVALUATION_E2E_REPORT` قبل حساب القبول. دونها تبقى الدقة والهلوسة والمقاييس البشرية غير مقاسة. لا تعتمد اختبارات الاسترجاع القديمة كإثبات قبول هذه البنية.

## الرجوع والإعدادات الأخرى

نسخة الكود قبل التغيير محفوظة خارج المستودع. `AI_ARCHITECTURE=legacy` وسيلة انتقال مؤقتة لمسار المحادثة السابق، مع بقاء مزود OpenAI الحالي وضوابط قاعدة البيانات؛ ليست استعادة كاملة للإصدار السابق. الرجوع الكامل يكون في نشر منفصل من النسخة المحفوظة، مع خطة قاعدة بيانات تمنع فقد البيانات الجديدة. لا تحذف جداول `0016` تلقائيًا؛ الفهارس القديمة محفوظة لهذا الغرض.

SMTP_HOST وSMTP_PORT وSMTP_USER وSMTP_PASSWORD وSMTP_FROM تفعل استعادة كلمة المرور. Google OAuth يستخدم GOOGLE_CLIENT_ID وGOOGLE_CLIENT_SECRET ورابط `${APP_URL}/auth/google/callback`. لترقية حساب معروف إلى مدير، من حاوية التطبيق:

```bash
npm run admin:promote -- your-email@example.com
```
