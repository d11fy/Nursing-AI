# Nursing AI — PostgreSQL & OpenAI

منصة تعليمية لطلاب التمريض: حسابات، محادثات ذكاء اصطناعي، صور، ملفات، وقاعدة معرفة RAG مدعومة بالكامل عبر OpenAI.

## النشر على Dokploy

1. أنشئ **Database → PostgreSQL** باسم خدمة مثل `nursing-ai-db` واسم قاعدة `nursing_ai`. صورة `postgres:18` العادية تعمل؛ لا تحتاج Supabase أو pgvector. شغّل قاعدة البيانات واحتفظ بكلمة المرور.
2. في خدمة التطبيق اربط مستودع `d11fy/Nursing-AI`، فرع `main`، والمسار `/`. اختر **Nixpacks**؛ ملف `nixpacks.toml` يضبط Node.js 22 وأوامر البناء والتشغيل.
3. في **Environment** أضف المتغيرات التالية واحفظها:

| المتغير | القيمة |
| --- | --- |
| DATABASE_URL | رابط الاتصال **الداخلي** من خدمة PostgreSQL |
| APP_URL | رابط الموقع الكامل باستخدام HTTPS |
| AUTH_SECRET | قيمة عشوائية سرية بطول 32 حرفًا على الأقل |
| AI_PROVIDER | `openai` |
| OPENAI_API_KEY | مفتاح الـ API الخاص بـ OpenAI |
| OPENAI_CHAT_MODEL | `gpt-5.4-mini` |
| OPENAI_VISION_MODEL | `gpt-5.4-mini` |
| OPENAI_EMBEDDING_MODEL | `text-embedding-3-small` |

ولّد AUTH_SECRET على جهازك بهذا الأمر؛ لا تنشر القيمة في GitHub:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

4. أضف دومين في **Domains** واجعله يوجّه إلى منفذ التطبيق `3000`، وفعّل HTTPS. لازم يطابق الرابط قيمة APP_URL؛ جلسات الدخول تستخدم cookies آمنة تتطلب HTTPS في الإنتاج.
5. انشر التطبيق. أمر البناء `npm run build`، وأمر التشغيل `npm run start`. أمر التشغيل الخاص بالمشروع يتحقق من الإعدادات وينشئ ويرقّي الجداول تلقائياً قبل تشغيل الموقع.
6. افتح `/register` وأنشئ حسابًا. لترقيته إلى مدير نفّذ من طرفية **حاوية التطبيق**:

```bash
npm run admin:promote -- your-email@example.com
```

## مزود الذكاء الاصطناعي (OpenAI)

- **نموذج المحادثة والرؤية الأساسي:** `gpt-5.4-mini` للمحادثات، قراءة الصور الطبية، والملفات.
- **نموذج التضمين (Embeddings):** `text-embedding-3-small` لبناء قاعدة المعرفة والبحث الدلالي (RAG).
- يتم تقسيم الملفات إلى مقاطع مع الاحتفاظ برقم الصفحة، وتخزين التضمينات والنصوص في PostgreSQL. البحث يجمع التشابه الدلالي والكلمات وعناوين الملفات، ثم يرتب المقاطع حسب السؤال. لا يتم إرسال الكتاب كاملًا مع كل سؤال.

### إعادة فهرسة المعرفة (Reindexing)

لإعادة فهرسة المستندات باستخدام تضمينات OpenAI:

```bash
npm run knowledge:reindex
```

## الإجابة تلقائيًا من الكتب والمحاضرات

هذا النظام يستخدم **RAG** للبحث في المصادر المرفوعة عند كل سؤال؛ لا يغيّر أوزان نموذج OpenAI ولا يتطلب من الطالب ذكر اسم الكتاب. يمكن كتابة سؤال بالعربية أو الإنجليزية، ويولّد النظام استعلامات بحث مناسبة، ثم ينتقي الأدلة من الملفات الجاهزة والمتاحة للطالب. عند اختيار مادة ينحصر البحث فيها؛ وعند فتح محاضرة خاصة يبقى البحث داخل محاضرة صاحب الحساب. لا تدخل ملفات الطلاب الخاصة في المعرفة المشتركة تلقائيًا.

تمر الإجابة النصية بمراحل فهم السؤال، وبحث دلالي وكلمي، وإعادة ترتيب حتى 24 مقطعًا لاختيار 8، ثم توليد إجابة مع اقتباسات داخلية. يتحقق التطبيق أن الاقتباسات موجودة فعلًا، ويجري مراجعة مستقلة لدعم الادعاءات والأرقام قبل عرض الإجابة مع اسم المصدر ورقم صفحة الملف. عند نقص الأدلة أو تعارضها يصرّح بذلك بدل تخمين إجابة. هذه الضوابط تقلل الأخطاء لكنها لا تضمن دقة 100%، ولا تغني عن مراجعة المدرّس للمادة الطبية.

استخراج PDF يحافظ على ترتيب الصفحات ويستخدم OpenAI Vision للصفحات قليلة النص أو ذات النص التالف. حد القراءة البصرية الافتراضي `KNOWLEDGE_MAX_OCR_PAGES=200` لكل ملف؛ إذا تجاوز الملف الحد تفشل المعالجة برسالة واضحة دون اعتماد فهرس جزئي. يمكن تقسيم الملف أو زيادة الحد بعد مراعاة تكلفة OpenAI والوقت. لا تزال جودة المسح والصور والجداول المعقدة تؤثر في النص المستخرج، ولا يُجرى OCR لكل رسم داخل صفحة ذات نص كافٍ. ملفات DOCX وPPTX وXLSX تعتمد استخراج النص الأصلي؛ حوّل الملفات المصوّرة أو صيغ Office القديمة إلى PDF واضح. صور المحادثة تستخدم مسار Vision الحالي؛ مراجعة الاقتباسات الجديدة تخص الإجابات النصية المبنية على المنهج.

### تفعيل الفهرس الجديد للمصادر الموجودة

Migration `database/0011_curriculum_search.sql` إضافية: تنشئ فهارس البحث الكلمي وحقول تغطية الاستخراج دون حذف الملفات أو المقاطع أو تغيير أبعاد التضمين. ينفذها `npm start` تلقائيًا، أو نفّذ من حاوية التطبيق:

```bash
cd /app
npm run db:migrate
npm run knowledge:reindex -- --stale-only
```

الأمر الثاني يعالج الملفات ذات الفهرس القديم أو الحالة الفاشلة بالتتابع، مستخدمًا `DATABASE_URL` و`OPENAI_API_KEY` في بيئة التطبيق. يمكن أيضًا اختيار «إعادة المعالجة» من قائمة الملف في `/admin/knowledge`. تُعرض تغطية الصفحات والصفحات المقروءة بصريًا بعد المعالجة. لا تُستبدل مقاطع الكتاب السابقة إلا بعد نجاح استخراج وتضمين جميع المقاطع؛ الملف الفاشل يستبعد من الإجابات ويعرض سبب الفشل. البحث الكلمي يعمل على الفهرس القديم بعد الـmigration، لكن تحسين الاستخراج يحتاج إعادة المعالجة. عند تغيير نموذج التضمين أعد فهرسة جميع الكتب بالأمر بدون `--stale-only`.

### التحقق والتقييم

```bash
npx tsc --noEmit
npm run lint
npm test
npm run build
node --conditions=react-server --import tsx scripts/evaluate-curriculum.ts --live
```

الاختبارات الآلية تغطي عزل بيانات الطلاب، اختيار الكتب دون تسميتها، الاقتباسات المختلقة، رفض الإجابات غير المسندة والتعارض، وقراءة الصفحات المصوّرة. أمر `--live` يرسل أمثلة اصطناعية صغيرة إلى OpenAI ويستهلك رصيد API؛ هو اختبار أولي لسلوك النموذج وليس قياسًا شاملًا للدقة الطبية. اختبر أيضًا أسئلة فعلية من كتبك بإجابات وصفحات مرجعية راجعها المدرّس. مرحلة المراجعة تضيف زمنًا وتكلفة، لذلك تعرض الواجهة «جارٍ البحث في المصادر ومراجعة الإجابة» حتى اكتمالها.

# OpenAI Setup

يستخدم المشروع OpenAI للمحادثة العادية، الصور، تحليل الملفات، والـembeddings.

أضف إلى ملف البيئة:

```ini
AI_PROVIDER=openai
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_CHAT_MODEL=gpt-5.4-mini
OPENAI_VISION_MODEL=gpt-5.4-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

ثم طبّق migrations وشغّل المشروع:

```bash
npm run db:migrate
npm run dev
```

يستخدم النظام OpenAI لكل عمليات الذكاء الاصطناعي في الموقع.
