
## 2) الفحوص لكل كتاب (من التطبيق ومن الويب)

| # | الفحص | ماذا تكتب | المتوقع | كتاب 1 | كتاب 2 | كتاب 3 |

| 2.13 | سؤال محدد داخل فصل | «ما هو <مصطلح من فصل X> في الفصل Y» | الجواب من الفصل Y فقط، أو يقول إنه لا يجده فيه | | | |

التحقق على الخادم لأي إجابة (من لوحة الإدارة أو SQL):

```sql
select m.created_at, t.diagnostics_json->'study' as study, t.final_source_ids_json
  from message_ai_traces t join messages m on m.id = t.message_id
 where t.conversation_id = '<conversation id>' order by m.created_at desc limit 10;
-- المقاطع المستشهد بها كلها من الفصل المطلوب:
select distinct chapter_index, chapter_title from knowledge_chunks where id = any(array(select jsonb_array_elements_text(final_source_ids_json)::uuid from message_ai_traces where message_id = '<assistant message id>'));
```

## 3) انقطاع البث ودورة حياة التطبيق (هاتف حقيقي)

سجّل في كل صف: ما رأيته، وهل ظهرت الإجابة، وهل تكرر السؤال/الإجابة، وهل خُصم أكثر من سؤال.

| # | السيناريو | الخطوات | المتوقع | النتيجة |
|---|---|---|---|---|
| 3.1 | Wi-Fi ← بيانات | أثناء كتابة إجابة طويلة بدّل الشبكة | «انقطع الاتصال، جارٍ التحقق من الإجابة...» ثم تظهر الإجابة المحفوظة. لا رسالة «انقطع الاتصال قبل حفظ الإجابة» | |
| 3.2 | خلفية ← مقدمة | أرسل سؤالًا واذهب للخلفية 30 ثانية ثم ارجع | تظهر الإجابة كاملة أو تُستكمل | |
| 3.3 | قفل الشاشة | أرسل ثم اقفل الشاشة دقيقة وافتحها | نفس 3.2 | |
| 3.4 | إغلاق وفتح | أرسل ثم أغلق التطبيق من المهام وافتح المحادثة | الإجابة في السجل إن اكتملت؛ وإلا شريط «ما زال المعلم يجهز الإجابة» ثم تظهر | |
| 3.5 | وضع الطيران | فعّله أثناء الإجابة ثم أطفئه بعد دقيقة | تتعافى الإجابة؛ أثناء الانقطاع رسالة عدم الاتصال | |
| 3.6 | إعادة المحاولة | فعّل الطيران قبل الإرسال مباشرة ثم أرسل ثم أطفئه واضغط «إعادة المحاولة» | تظهر إجابة واحدة | |
| 3.7 | لا تكرار ولا خصم مزدوج | بعد 3.1–3.6 نفّذ الاستعلامين أدناه | `chat_generations`: صف واحد `completed` لكل سؤال؛ الحجوزات `committed` بعدد الأسئلة | |
| 3.8 | زر الإيقاف | اضغط «إيقاف» أثناء إجابة | تتوقف؛ لا تظهر رسالة خطأ | |
| 3.9 | تطبيق قديم (1.2.0) | افتح 1.2.0 واسأل ثم اقطع الشبكة | تُحفظ الإجابة على الخادم وتظهر في السجل (دون واجهة التعافي) | |

```sql
select status, attempts, error_code, count(*) from chat_generations
 where created_at > now() - interval '2 hours' group by 1,2,3 order by 1;
select status, count(*) from usage_reservations

```

**قبل النشر انتبه:** `app/api/app/version/route.ts` يعيد `force_update=true` لكل عميل أقدم عندما يكون `latest_version_code ≥ MINIMUM_MOBILE_VERSION_CODE` (حاليًا 5) والملف موثّق. أي إصدار منشور بعد 1.2.0 سيجبر مستخدمي 1.2.0 على التحديث. إن أردته اختياريًا غيّر `MINIMUM_MOBILE_VERSION_CODE` أو القاعدة قبل النشر.

عند الاعتماد فقط (النشر):

1. `node scripts/build-android.mjs --release --publish-staged` — يتحقق من أن الملف المنشور هو نفسه الذي اختُبر (SHA-256) ومن الشهادة والإصدار، ثم ينسخه إلى `public/downloads/nursing-ai-v1.2.1.apk` و`nursing-ai-latest.apk`.
2. حدّث `DEFAULT_APP_VERSION` في `lib/version/app-version.ts` (1.2.1 / 6 / الحجم / SHA-256) وأضف ترحيلًا يماثل `0029` لإعداد `mobile_app_version`، أو عدّل الإعداد من لوحة الإدارة → الإعدادات بالقيم التي طبعها الأمر. **لا ترفع `nursing-ai-latest.apk` قبل تحديث الإعداد في الوقت نفسه**؛ وإلا يرى الخادم عدم تطابق البصمة ويوقف التنزيل (`integrity=mismatch`).
3. تحقق من `/download` و`/api/app/version` (`latest_version=1.2.1`, `available=true`) وجرّب تنزيل الملف ومطابقة SHA-256.
